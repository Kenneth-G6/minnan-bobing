## 一、项目背景与目标

现有版本只有一种玩法：**经典博饼**——六个奖池（一秀 32 / 二举 16 / 四进 8 / 三红 4 / 对堂 2 / 状元 1），先到先得，五个普通奖池发完即收官。

本次新增第二种玩法**状元争**：不博普通奖，只争状元。玩家的每一次回合都持续掷骰直到博出状元类奖项，一圈之内无人能超越当前擂主，擂主即夺冠。

目标：

1. 新增状元争模式的完整可玩闭环（回合制 → 抢位 → 收官 → 结算），规则写死在 core 层。
2. **经典模式行为零改动**——这是本迭代的硬性约束，判定链、奖池、结束条件、文案一律不碰。
3. 两种模式在开始界面自由选择，互不干扰。

## 三、规则定义（写死在 core，不可配置）

### 3.1 判定

判定链沿用现状（13 级有序判定链，命中即停），本模式只认可 **四红及以上 7 级**：

| 等级 | 名号 | 组合 | 组合数 | 单掷命中率 |
| ---: | :--- | :--- | ---: | ---: |
| 12 | 状元插金花 | 4 个 4 + 2 个 1 | 15 | 0.0321% |
| 11 | 六杯红 | 6 个 4 | 1 | 0.0021% |
| 10 | 遍地锦 | 6 个 1 | 1 | 0.0021% |
| 9 | 六勃黑 | 6 个 2/3/5/6 | 4 | 0.0086% |
| 8 | 五王 | 5 个 4 | 30 | 0.0643% |
| 7 | 五子 | 5 个同点（非 4） | 150 | 0.3215% |
| 6 | 四红 | 4 个 4 | 360 | 0.7716% |
| — | **合计** | — | **561** | **1.2024%** |

一秀、二举、四进、三红、对堂在本模式中**不存在**（既不发放也不显示），普通奖池整套不参与。

### 3.2 回合（turn）

当前玩家连续掷骰，**直到判定为状元类为止**。

- 中间掷骰称为「过程掷骰」，不产生结果、不进入历史记录、界面不显示「未博中」
- 一个回合必然以一个状元类结果收尾
- 单回合重掷次数的理论分布：均值 83 次，中位 57 次，p90 190 次，p99 381 次

### 3.3 圈（round）与擂主

- **第 1 圈**：全部 N 位玩家各完成 1 个回合。首个博出状元类者成为**擂主**，其后玩家的结果与当前擂主比较
- **第 2 圈起**：除擂主外的 N−1 位玩家各完成 1 个回合
- **擂主不掷骰，只守擂**

### 3.4 抢位

| 情形 | 判定 | 结果 |
| :--- | :--- | :--- |
| 尚无擂主 | — | 该玩家成为擂主 |
| 结果严格大于擂主 | `replaced` | 抢位成功，成为新擂主 |
| 结果等于擂主 | `kept` | 不替换（先到先得） |
| 结果小于擂主 | `kept` | 守擂成功 |

比较逻辑复用 `compareRolls`（先比 level，再按 `tiebreak` 字典序降序），与经典模式逐字一致。

### 3.5 收官

**一圈博完，无人在这一圈内抢位成功，则擂主定格夺冠。**

- 抢位成功则重新计一圈（本圈剩余玩家继续与新擂主比，圈结束后再开新圈）
- 第 1 圈若无人抢位，同样立即收官
- 不存在「无人博中」导致无法结束的可能——每个回合必然博中一次

### 3.6 结算

擂主获得唯一一份状元饼（`pool.zhuangyuan` 归 0），其余玩家无奖品，但保留各人本次的最佳成绩用于展示。

## 四、玩法数据（设计依据，模拟 3 万局）

### 4.1 一局规模

> 下表由**真实引擎**（`createGame('zhuangyuan')` + `takeTurn`）每种人数跑 **3 万局**实测，脚本为本地一次性实验、未入仓。

| 人数 | 平均掷骰 | 中位 | p10 | p90 | p99 | 平均回合数 | 平均圈数 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2 | 223 | 188 | 61 | 427 | 720 | 2.7 | 1.51 |
| **4** | **513** | 464 | 214 | 874 | 1333 | 6.2 | 1.88 |
| **6** | **802** | 736 | 380 | 1313 | 1912 | 9.6 | 2.02 |
| 8 | 1081 | 1003 | 555 | 1721 | 2479 | 13.0 | 2.08 |
| 12 | 1647 | 1526 | 908 | 2551 | 3664 | 19.8 | 2.15 |

**与经典模式相反**：本模式一局的掷骰数与人数强相关（每个回合都要独立重掷到中状元，人越多回合越多），而经典模式的约 220 掷与人数无关（同批脚本对照：2 人 219.4 / 4 人 219.8 / 6 人 220.2 / 12 人 223.1 掷）。

### 4.2 最终擂主名号分布

| 擂主名号 | 插金花 | 六杯红 | 遍地锦 | 六勃黑 | 五王 | 五子 | 四红 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 4 人 | 15.5% | 0.9% | 0.9% | 3.6% | 22.5% | 47.2% | 9.4% |
| 6 人 | 22.8% | 1.4% | 1.4% | 5.2% | 27.5% | 38.6% | 3.1% |

关键结论：**插金花是统治级结局**（一旦出现无人可超越，当圈必然收官），四红则最容易被抢走。

### 4.3 对设计的直接影响

1. 一局 513～802 掷（4～6 人），按现有的 1.3 秒/掷动画要播 11～17 分钟，**必须重新设计演出节奏**（见 5.2）。
2. 单回合重掷次数长尾严重（4 人局实测：均值 83.8、中位 59、p90 190、**p99 375**、最大 789），**单回合动画必须封顶**。
3. 历史记录不能再按「每一掷」记（会出现上千条），改为**按回合记**。

## 五、功能需求

### 5.1 开始界面

- 新增**模式选择卡片**两张，选中态明确：
  - 「经典博饼」——博全套奖品，五个普通奖发完收官
  - 「状元争」——只争状元，掷到博出状元为止，一圈无人超越即夺冠
- 「规则速览」随模式切换：
  - 经典：维持现状（13 级判定表 + 六个奖池 + 现有说明文案）
  - 状元争：7 级判定表 + 回合制与收官说明 + 量级提示（「一局平均约 513 掷（4 人），多数时间在等一次博中」）
- 玩家人数、姓名输入沿用现状

### 5.2 自动重掷演出（核心技术需求）

| 阶段 | 表现 |
| :--- | :--- |
| 过程 | 骰子在碗中快速翻滚，碗边「已掷 N 次」计数快速跳动；**不逐次刷新骰面、不显示任何「未中」文案** |
| 节奏 | 默认单次间隔 **60ms**；提供 **×2 / ×4 / 直接看结果** 三档加速 |
| 封顶 | **单回合过程时长硬上限 5 秒**；超出则按 `interval = clamp(5000/rolls, 12, 60)` 自动加速 |
| 命中 | 切换为完整落碗定格动画 + 金效 + 音效，显示名号与组合说明、以及守擂/抢位结果 |
| 收官 | 沿用现有 fanfare 与自动跳转结算的延迟 |

时间预算（默认档）：每回合 ≤ 5 秒过程 + 约 1.5 秒命中演出 → **4 人局约 45～55 秒，6 人局约 80～95 秒**；加速档约减半。

### 5.3 游戏界面

| 区域 | 经典模式（不变） | 状元争 |
| :--- | :--- | :--- |
| 顶栏 | 「第 X 轮」+ 剩余普通奖 + 人数 | 模式徽章 + 「本圈还剩 N 人待博」 |
| 中栏 | 博饼碗 + 结果区 + 掷骰按钮 | 同上，改为「博一次」按钮 + 自动重掷演出 |
| 右栏 | 奖池 + 历史记录 | **擂主榜**（擂主卡片 + 各人最佳成绩排行 + 累计掷骰数）+ 回合记录 |
| 玩家列表 | 现有高亮与状元标记 | 擂主标记「守擂中」，当前回合玩家高亮 |
| 结果区 | 现有 13 级播报 | 仅博中时显示名号，过程阶段只显示计数 |

### 5.4 结算界面

- 擂主加冕（复用现有加冕视觉），显示名号、组合说明
- 「战果」区改为**各人最佳成绩榜**（按成绩降序），并标注每人累计回合数与掷骰数
- 结束原因文案：「本圈无人抢位，状元定格」
- 「重新开始」「再来一局」行为按模式沿用

## 六、技术方案

### 6.1 分层与约束

沿用项目现有约定：核心规则全部在 `src/core/` 内、零 UI 依赖；随机源可注入；所有状态变更返回新对象。

### 6.2 数据结构

```ts
export type GameMode = 'classic' | 'zhuangyuan';

export interface GameState {
  mode: GameMode;                    // 新增
  // ── 经典模式字段全部保留，行为不变 ──
  players: Player[];
  pool: PrizePool;
  currentIndex: number;
  round: number;
  zhuangyuan: { playerId: number; result: RollResult } | null;
  history: HistoryEntry[];
  status: 'playing' | 'finished';
  settled: boolean;
  // ── 状元争专用 ──
  challengersLeft: number | null;    // 本圈还差几人未博；经典模式恒为 null
  totalRolls: number;                // 累计掷骰数（含过程掷骰）
}

export interface Player {
  id: number;
  name: string;
  prizes: Record<PrizeKey, number>;
  best: RollResult | null;           // 新增：本局最佳成绩（状元争展示用）
}

export interface TurnOutcome {
  playerId: number;
  playerName: string;
  rolls: number;                     // 本回合重掷次数
  dice: number[];                    // 最终骰面
  result: RollResult;                // 必为状元类（type === 'zhuangyuan'）
  change: ZhuangyuanChange;          // became | replaced | kept
  round: number;
  finished: boolean;
}
```

### 6.3 core 接口

| 接口 | 说明 |
| :--- | :--- |
| `createGame(names, mode: GameMode = 'classic')` | 默认值保证既有调用与测试不受影响 |
| `takeTurn(state, random)` | **状元争专用**。算完一个完整回合，返回 `{ state, outcome, sequence }`。`sequence` 为过程掷骰的骰面序列，**仅供动画播放，不写入 state** |
| `rollOnce(state, random)` | 经典模式沿用；状元争模式下调用直接抛错（fail fast） |
| `isFinished(state)` | 结束判定按模式分派：经典 = 普通奖池全空；状元争 = 本圈博完且无人抢位 |
| `rollOnce` 与 `takeTurn` 共用 | `settle()`、`zhuangyuanPlayer()`、`countPrizes()` 全部复用 |

`takeTurn` 实现要点：

1. 循环掷骰直到 `judgeRoll(dice).type === 'zhuangyuan'`，累加 `rolls` 并收集 `sequence`
2. 安全上限：单回合超过 100000 次掷骰直接抛错（防注入随机源有 bug 导致死循环）
3. 按 3.4 判定抢位；更新 `challengersLeft`（抢位成功则重置为 N−1，否则递减）
4. `challengersLeft` 归零且本圈无人抢位 → 收官并结算
5. 历史只追加 1 条**回合级**记录；过程掷骰不入历史

### 6.4 演出实现要点

- `sequence` 只在组件内短暂持有，用 `setInterval` + 索引推进播放，播完即释放，不进 React 状态树
- 计数与骰面刷新分离：计数每 tick 更新，骰面仅在部分 tick 刷新，降低重渲染压力
- 组件卸载、退出确认、加速档切换时清理计时器（沿用现有 `timersRef` 模式）
